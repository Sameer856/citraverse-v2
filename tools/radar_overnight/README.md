Run `caffeinate -i /private/tmp/citra-cloud-venv/bin/python -u tools/radar_overnight/run.py` from the project root. Requires the existing ignored `.cloud-local/pairing.json`, `httpx`, and `websockets`. Never copy credentials into the source or the report.

## Bounded static-return repeat

The aggressive frequency/explicit-CFAR sweep remains stopped. After a prolonged stable baseline, `crossover.py` can repeat only the previously successful literal-CFAR static-retention flag (`static_rm=0`) for two consecutive 20-minute windows, restore the original baseline for 20 minutes, then continue baseline-only observation. This changes no other requested parameter, Wi-Fi, firmware or startup save. It aborts additional alternate windows on a reboot, stale-radar status, failed fresh-rate gate or external operator change. Set `RADAR_CROSSOVER_EXPECTED_BOOT` to the just-verified boot ID to refuse a test after a new reset. The execution plan and any recovery are logged separately; the earlier suspension record is retained. Rollback and external-change handling have simulated control-flow tests.

`density_bed.py` is a separate exploratory density-core grid, trained only on windows 000, 003, 008 and 009. Its frozen candidate is replayed by `replay_density_runtime.mjs` with the exact JavaScript tracker. It does not overwrite the earlier method or its independent results. Each frozen engine has a source hash; changes must not silently redefine its prospective validation. Pre-freeze comparisons, selected development windows, prospective baseline windows and prospective alternate profiles are labeled separately. Retained historical-only candidates do not count as recent detections.
